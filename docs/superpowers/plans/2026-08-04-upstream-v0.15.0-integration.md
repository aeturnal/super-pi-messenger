## Conflict Handling Protocol

For every conflicted cherry-pick:

1. Run `git status --short` and `git diff --cc -- <paths>`.
2. Classify each conflict as mechanical, fork identity, or meaningful behavior.
3. Resolve mechanical conflicts without choosing an entire side wholesale.
4. Retain both fork and upstream changelog entries in chronological/logical sections.
5. For a meaningful behavior conflict, leave the cherry-pick paused and ask the user before editing the conflicted behavior.
6. If the chosen resolution needs fork-specific code, first add a regression test that fails once conflict markers are removed, then implement the smallest adaptation.
7. Run `git diff --check` and search for unresolved markers before `git add`:

```bash
rg -n '^(<<<<<<<|=======|>>>>>>>)' --glob '!node_modules/**' .
git diff --check
```

8. Continue with `git cherry-pick --continue`; never replace the original author.
9. Update the integration report with the conflict, decision, files, and verification evidence.
